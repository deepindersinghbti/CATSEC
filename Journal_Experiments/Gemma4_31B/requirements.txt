# cuDNN and a matching PyTorch build already installed, so torch is

# the template risks a CUDA/driver mismatch.
#
# IMPORTANT: `pip install -r requirements.txt` alone does NOT give you a
# working vLLM + Gemma 4 setup. As of now, stable vLLM on PyPI still pins
# transformers<5, but Gemma 4's model_type ("gemma4") is only recognized by
# transformers>=5.5.0 — pip's resolver either conflicts outright, or installs
# "successfully" and then fails at model-load time with:
#   "The checkpoint you are trying to load has model type `gemma4` but
#    Transformers does not recognize this architecture."
# (tracked upstream: vllm-project/vllm#38868, #39216 — still open)
#
# vLLM + transformers are therefore installed SEPARATELY, after this file,
# via install_vllm_gemma4.sh (nightly wheel). Everything below is safe to
# install normally.
